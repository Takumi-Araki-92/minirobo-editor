# Robot Scene Studio — 時間軸実行型演出エディター — 時間軸実行型演出エディター

## 配布版の起動

配布ZIPを解凍し、中の`robot-scene-studio`フォルダーをVS Codeで開いてください。
WindowsではNode.js未導入でも起動スクリプトが自動準備します。
通常の起動にはPython、uv、npm依存のインストールは不要です。

```powershell
.\start.ps1
```

VS CodeとGitHub Copilotを利用できる状態で、このフォルダーを開き、
エージェントモードで「起動して」と指示すると、同梱の手順に従い準備から起動・HTTP確認まで進めます。
Node.js 22以上が見つからなければ、公式 `https://nodejs.org` から最新の対応LTSのWindows ZIPと
SHA-256一覧を取得し、照合後に `%LOCALAPPDATA%\RobotSceneStudio\runtime`へ展開します。
管理者権限・恒久PATH変更・既存Node.jsの置換は不要です。再起動時は準備済みのものを再利用します。
初回だけ外部ダウンロードが必要で、プロジェクトや履歴は外部送信しません。
通信・プロキシ・組織ポリシー・実行承認で拒否された場合は理由を表示して停止し、
TLSやセキュリティ設定を無効化しません。配布ZIPにNode.js本体は含めません。
準備だけの確認は `.\start.ps1 -PrepareOnly` です。
ユーザー専用ランタイムは本アプリの起動にのみ使い、システム全体のNode.jsは変更しません。
復旧は既存Node.jsを `-NodePath` で明示するか、組織が許可した導入方法を使用してください。
今回作成されたランタイムを取り除く場合は、本アプリ停止後に該当バージョンのフォルダーだけを削除します。
作業履歴の `data\history` は削除しないでください。

VS Code／Copilotの導入・サインイン、ZIP展開とフォルダーを開く操作、エージェントモード選択、
ワークスペースの信頼・コマンド実行・ダウンロードの承認は利用者の操作が必要です。
Copilotが動く前の準備や、組織が禁止した処理まで無条件に自動実行する仕組みではありません。

PowerShellの実行ポリシーでスクリプトを実行できない場合は、ポリシーを変更せず
導入済みNode.jsの `node server.js`で起動できます。Node.js未導入でスクリプトも禁止の場合は、
組織が許可した導入が必要です。ブラウザーで`http://localhost:3100`を開きます。
終了はサーバーのターミナルでCtrl+Cを一度押して待ってください。
同梱の`AGENTS.md`と`.github/copilot-instructions.md`にCopilot向けの手順があります。
`/init`はCopilotの製品・バージョンにより動作が異なり、起動を保証するコマンドではありません。
読み込み後に「このフォルダーのAGENTS.mdに従ってエディターを起動して」と指示してください。
対応するVS Codeでは、同梱の`/start`プロンプトも使えます。

このZIPは標準マップのみを含み、作業データ・履歴・社内設定・Node.js本体・
`node_modules`・ブラウザー本体を含みません。各利用者のPCで独立して動作します。
待ち受けはローカルPC限定のままです。LAN公開・認証・共同編集はこの配布に含みません。

## 永続する編集履歴とロールフォワード

今後の**確定した編集操作ごと**に、全マップを含む状態を`data/history`へ保存します。
移動・リサイズのドロップ、設定の適用、名称変更、削除、新規作成、JSON読込、
Undo/Redoが対象です。マウス移動、再生位置、未適用のダイアログ内操作は対象外です。
導入前のUndoスタックや、既に失われた過去の操作は復元できません。

- 「編集履歴」から任意の状態を適用できます。後の履歴を削除せず、新しい履歴として追加します。
  以前の状態へ戻した後も、さらに後の履歴を選び直してロールフォワードできます。
- 起動時はPC上の最新履歴を復元します。ブラウザー内の状態と異なる場合、
  ブラウザー側の元データを`robot-scene-studio.backup.before-server-history`へ退避します。
  ブラウザーを消去しても、同じサーバーフォルダーの履歴から復元できます。
- フッターの「履歴保存済み · #番号」が保存完了です。保存中に終了しないでください。
  送信待ちの操作はブラウザーにも一時退避し、再起動時に再送します。
  ただし未送信のままブラウザーデータを消すと、その未送信分は失われます。
- 保存失敗・容量不足・別画面との競合は表示し、それ以上の編集を拒否します。
  「編集履歴」→「未送信履歴を再試行」、またはJSON保存で退避してください。
  競合時は上書きせず、JSON退避後に再読込して調整してください。
- ディスク上の履歴は自動削除・件数制限を設けません。各回の完全な状態を保存するため、
  背景画像や操作数に応じて容量が増えます。保存先の空き容量を管理してください。
- JSON保存は現在の状態のみです。全履歴の持ち運び・バックアップはサーバーを正常終了し、
  `data/history`フォルダー全体を別途コピーしてください。配布ZIPには履歴を入れません。
  削除した情報も履歴に残るため、履歴の共有・保管先の権限に注意してください。

保存形式は連番のJSONスナップショットとSHA-256検査値です。一時ファイルへの書き込み・
同期後に確定します。破損・番号抜けは黙って無視せず起動を停止します。
同じ保存先を複数サーバーで開くことはできません。
強制終了後に`writer.lock`だけが残った場合、同じフォルダーを使うNodeサーバーが
**稼働していないことを確認してから**、`data/history/writer.lock`だけを削除して再起動してください。
連番JSONや履歴フォルダーを消さないでください。

適用順は現在の作業をJSON保存→サーバーを停止→新版で起動→履歴保存済み表示を確認、です。
問題があればJSONへ退避してサーバーを停止し、元のコードと元の作業JSONへ戻せます。
履歴データは保全してください。履歴保存は障害対策用の別媒体バックアップの代わりにはなりません。

Node.js 22以上／Edge・Chrome。黒基調のデザインを保ち、**1マップ＝1シーケンス**の
複数タブ、時間軸上のアクション、人間グループ、部屋の状態表示を編集します。
実機への指令・測位接続は行いません。座標はNode.js版ArUco測位
（`robot_pose/v3`）と同じ左下原点・1600×900・X右／Y上・右0°／反時計回り正です。
Python版の左上原点・百分率座標とは異なります。将来連携の契約と注意点は
[INTEGRATION.md](INTEGRATION.md) を参照してください。

## v4/v5：時間軸の実行仕様

- 画面の版表示は **α 0.6** です。旧標準名のテストマップ（`マップ 1 · テスト`、
  `最新テスト · 人物5人`、`Smart Building Fleet Demo`）は読込時に削除し、
  現行の「テストマップ」1件へ整理します。既存の現行テストがあればそちらを残します。
  その他のマップと名前を変更したマップは削除しません。更新前の自動保存は
  `robot-scene-studio.backup.before-old-demo-removal`へ退避します。
  上部の「最新テストマップ」は現行テストのタブを開き、重複追加しません。
  現行テストがない場合だけ確認して追加します。最大8タブの制限は変わりません。
- **タブ名はダブルクリックで直接編集**できます。Enterまたはフォーカス移動で確定、
  Escapeで取消。空の名前はエラーにして確定しません。Undo/Redo・自動保存に対応します。
- バーの移動・右端の幅変更中に**Shiftを押すと、他のバーの開始／終了へ8px以内で吸着**します。
  移動は自分の開始／終了のうち近い側、幅変更は終了側を揃えます。
  吸着先の時刻と項目名を縦ガイドで表示し、Shiftを離すと通常操作へ戻ります。
  ズーム・横スクロール後も同じ画面上の距離で判定します。Escape・フォーカス喪失で取消、
  ドロップで確定します。バーの重複などの安全エラーは従来どおり残ります。
- コントロールを選ぶと、対応するロボット・人・部屋を光が走る枠で強調します。
  OSの動きを減らす設定では静止枠に切り替わります。
- ロボットの行設定で**清掃／警備／配送**を選べます。種別未保存の旧データは清掃表示です。
  車体は50インチ・16:9のフィールド換算で**100×100mm**（約144.54座標、2.89セル）。
  安全判定は角を含む半径約102.20座標の保守的な円です。旧版で通れた狭い経路や
  近接配置が接触エラーになる場合があります。JSON退避後、警告を確認して修正してください。
  バーや保存座標は自動移動しません。戻す場合は旧版と退避JSONを併用します。
- **接続ピン・エッジ・トリガー条件・合流は廃止しました。**
  すべての行でバーの開始時刻と長さだけを使います。「待機」は引き続き使えます。
  旧データの読込時は接続条件と合流項目を除去し、他のバーの位置・長さは保持します。
  自動保存の更新前データは`robot-scene-studio.backup.before-timeline-only`へ退避します。
  条件で止まっていた項目も指定時刻に動くため、更新後は通行警告と再生を確認してください。
  旧版へ戻す場合はコードと退避データの両方を戻します。
- マップ編集の「⚡ 充電スペース」で矩形の充電マスクを描けます。
  壁・障害物を追加しない透過領域で、選択削除・編集内Undo/Redoに対応します。
  充電動作・残量管理や実機予約は行いません。
- テストマップは初回起動・新規プロジェクトの**標準シナリオ**です。追加ボタンはありません。
  自動保存や読込済みの作業は勝手に置き換えません。別シナリオには「＋ シーケンス」を使います。
- 「＋ シーケンス」では、他タブのマップの縮小画像と名前を**ラジオボタン**で選べます。
  床・部屋・家具・充電領域・背景をコピーし、動作を空にして作成します。
  コピー元は変更せず、以後のマップ編集も各タブで独立します。最大8シーケンスです。
  「新しくマップを描く」も選べます。追加・取消・Undo/Redo・再読込に対応します。
- テストマップは会議室2室・WC・EV・広いエントランス・二度曲がる廊下・充電領域を備えます。
  32×18の全576セルを使い、左端のホールは**高さ900すべて・幅400**で、
  左へ続く矢印と見切れ表現を付けました。画面外への通行は許可しません。
  下の直線廊下と右端の縦廊下は6セル幅、上の廊下は5セル幅です。
  人物行「人間 · 会議参加者（5人）」を先頭に置き、初期画面から見つけられるようにしています。
  5人が0〜3秒に入室、3〜5秒の**2秒間**に会議、5〜8秒に退室します。
  旋回追加前は、警備ロボットが8〜14.5秒に待避、清掃ロボットが15〜54秒に
  会議後の清掃と充電場所への帰還を行います。同じ直線廊下へ同時進入させず、
  待機と通行時刻をバーへ組み込んだサンプルです。実機フリート制御ではありません。
  人間は旋回せず移動します。会議は3〜5秒の2秒間です。
  清掃の待機表示は3秒とし、移動・待避・帰還を展示の中心にしています。
  充電領域に重なっていた椅子は除去し、領域の中心を初期位置に選べます。
  充電領域自体は通行可能ですが、壁・家具・MAP外への接触は引き続き拒否します。
  自動ドアの扉は開口内でクリップし、開いた際に隣室へはみ出して描画しません。
  保存済み標準テストも更新します。独自に時刻や行構成を編集した場合は時刻全体を保持し、
  未編集の標準テストのみ短縮します。自動保存の更新前データは
  `robot-scene-studio.backup.before-short-demo` に退避します。
  復旧時はこの退避データをJSON保存して読み込んでください（短縮を再適用しないよう
  対象マップの`demoScenarioRevision`を`2`にします）。
- EVは階数表示・昇降矢印・金属調の扉と乗りかごで表現します。
  13個の机・椅子・植栽と、区別しやすいタイル・カーペット・木目・コンクリート床を配置しました。
  空間の見た目は部屋選択時の設定から「標準／エレベーター／画面外へ続くホール」を選べます。
- **ドアは原則施錠**です。部屋の行に「ドア解錠」を配置し、
  ドロップダウンから実際の部屋名を選ぶと「〇〇室解錠」のバーになります。
  そのバーの間だけ、選択室に属するドアが接近に反応して両側へスライドします。
  無関係な部屋のドアは、近づいても開きません。
  解錠中は車体外周から4グリッド以内で開き始め、2グリッド以内で全開です。
  バー終了時に通過中なら、車体半径＋10座標の範囲を抜けるまで開放を保持してから再施錠します。
  保持中に別の物体が近づくだけで開放期間を延長することはありません。
  再生・シークでも同じ開閉結果です。既定の「ストーリー確認」では、施錠中でも警告だけで
  移動を継続します。扉の開閉タイミングは後から調整でき、バーの時刻は変えません。
  「連携確認」を明示的に選んだ場合だけ、施錠中の通過と後続を停止します。
  実機の自動ドアには接続しません。

**既存シーケンスへの影響：**扉確認が未設定のマップは、読込時に「ストーリー確認」へ移行し、
履歴と保存JSONに明記します。指定済みの「連携確認」は維持します。
先にJSON退避→更新→移動と警告を確認→必要に応じて解錠バー調整→保存の順で適用してください。
扉表示は施錠のままでも移動できるため、実機の通行許可と混同しないでください。
旧版へ戻す場合は更新前JSONと旧版ZIPを併用してください。
- 目盛り・バー・再生ヘッドは同じ16pxの左余白を使います。
  正の実行時間のバー幅は短い項目でも秒数×ズーム倍率どおりで、最小幅に引き伸ばしません。
  0秒の表示消去などだけは操作用の12pxマーカーで表示し、左端が実行時刻です。
  イベント終了後は部屋への集約表示も解除し、ロボット・人を個別表示に戻します。
- **横位置＝開始予定秒、幅＝実行秒数**です。右へドラッグすると遅く開始し、
  移動・回転の幅を伸ばすと同じ距離・角度をゆっくり進みます。
  **左端＝開始、右端＝終了**です。安定待機0.3秒・空転・廊下待ちを加算しません。
  長さ0秒の項目は操作のため最小幅で描きます。
- 行内は左→右、同じ位置は保存配列順。前の完了が予定に間に合わない場合は
  **自動で遅らせずエラー表示して、その項目を停止**します。バーの重複もエラーです。
  配置時刻や幅を調整してください。既存のバーを勝手に移動・伸縮しません。
- **待機**は指定秒数その位置で停止します。「表示→待機→消去」と並べられます。
  表示・イベント発生は項目の開始時に反映し、**そのバーの右端で自動終了**します。
  表示を長く残す場合は表示バー自体を伸ばしてください。
- 実機遅延の模擬設定は画面から除き、旧データの期限・模擬失敗・安定待機は
  時間軸固定再生では使いません。実測位置は未取得（`null`）のままです。
  壁・家具への通行不可判定は維持します。狭い廊下の競合は自動待機で解消せず、
  通行時刻を調整するエラーを表示します。

**既存データの注意：**保存形式とバーの位置・幅は維持しますが、旧版で自動遅延に
依存していたデータは、行内重複・通行不可としてエラーになる場合があります。
先にJSONを退避し、更新後に警告を確認してバーを修正してください。
戻す場合は旧版と退避JSONを併用してください。
以下の自動待機・遅延・期限に関する過去の記述は旧互換モデルの説明で、
現在のエディターの時間軸固定再生には適用しません。
- 座標指定は**グリッド中央／自由座標**を切り替えられます。既定は50×50座標単位の
  グリッド中央（左下25,25／右上1575,875）で、既存データの位置は変わりません。
  自由座標ではMAP上で移動後のオブジェクトがカーソルに追従し、クリックで仮固定します。
  仮固定したオブジェクトを再クリックすると追従を再開し、「適用」で保存します。
  **Shiftを押している間は移動前の位置を基準に水平または垂直へ制限**し、離すと自由に戻ります。
  これは1本の直線の方向制限です。経由点・曲線移動は追加しません。
  初期位置・独立した表示位置でもモードを選べます。初期位置の自由指定は
  仮固定→MAP画面の「適用」→初期位置画面の「適用」で保存します。
  自由からグリッドへ切り替えると、その項目の位置をセル中央へ丸めます。
  自由座標でも壁・家具・領域外の通行判定は無効になりません。
- 移動先は選択時点で通行判定し、壁・家具・領域外に接触する経路を赤色にして
  理由をアラート表示します。自由座標ではカーソル追従中も更新します。
  正常な位置に戻すと警告を解除し、不正な経路は「適用」でも登録できません。
  エラー時は「適用」を無効にし、フォーム送信でも再検証してポップアップを閉じません。
  除外中の行・前の動作が失敗した行でも編集時の通行判定を省略しません。
  初期位置はMAPで指定し、数値入力欄は表示しません。不正な初期位置は警告し、
  初期位置の「適用」も無効にします。正しい位置をMAPで選び直すと有効になります。
  ロボット・人の最初の項目を追加するときは、先に
  **「初期位置をどこにしますか？」とMAPだけを中心にした画面**を開きます。
  MAPクリックだけでは確定せず、何度でも選び直せます。「適用」を押してから
  通常のアクション編集へ進みます。グリッド／自由座標の両方に対応します。
  同じMAP画面の「初期の向き（°）」で向きも設定でき、矢印で即時確認できます。
  右向き0°・上向き90°・下向き-90°です。位置と向きは右下の「適用」でまとめて確定し、
  閉じた場合はどちらも破棄します。不正な角度では適用できません。
  選ばず閉じた場合は初期位置も項目も変更しません。
  既存の先頭より早い時刻へ項目を挿入する場合も再確認しますが、
  既存項目の編集や後続への追加では表示しません。
  初期位置の確定は先に保存されるため、その後アクション編集を取り消しても位置は残ります。
- コントロールの項目をドラッグすると、タイムラインには配置予定秒のカード、
  MAPには配置予定位置のハイライトを表示します。対応しない行（例：部屋の行へ移動）、
  ロック中の行、MAP上の通行不可位置は赤い配置不可表示にし、ドロップを拒否します。
  MAPへの配置先の行は、現在選択中の行です。ハイライトは離脱・取消・ドロップ時に消えます。
- ロボット・人・部屋・表示の追加パレットはクリックとドラッグの両方に対応します。
  シーケンスへ近づけると追加予定の行を半透明で表示し、ドロップでその順番へ挿入します。
  アクションは対象の行全体と予定カード幅、MAP上の移動は経路と車体占有、
  部屋イベントは対象部屋全体をハイライトします。取消では追加しません。
  コントロール項目のドラッグでは、ハイライトの左端をカーソルへ合わせます。
  時間軸の余白・ズーム・横スクロールを考慮し、ドロップ後も同じ位置へ配置します。
  この新規配置は位置を正確に合わせるため時間スナップを行わず、既存カードの移動は従来どおりです。

### 通行・接近予測

- グリッド式MAPの壁・家具・未定義セル・領域外への直線移動を拒否します。
  ロボットは半径約102.20座標単位（100mm角の角まで包む円）、
  人は半径20座標単位の円形占有モデルです。回転時も同じ保守的な円で判定します。
  指定した車体近似の角は考慮しますが、実機寸法・付属物・人数分の広がりを保証する精密モデルではありません。
- ドアは潜在的な開口として扱います。単セルのドアはロボット幅より狭いので拒否する場合があります。
  必要な数を隣接配置して開口を広げてください。表示は接近による自動開閉ですが、
  実際のドアの開閉状態は未接続です。閉鎖・故障・施錠を再現するものではありません。
- 「廊下」種別で、各セルを通る連続した横／縦のセル数の小さい方が3以下のセルを
  連結した範囲を、1台ずつ通す区間とします。L字・狭窄部も安全側にまとめます。
  幅4セル以上の区間・大きい部屋にはこの排他制御を適用しません。
- 競合時は車体中心が入口へ入る約60.81座標単位手前で自動待機し、
  相手・廊下名・予約時間帯・待機秒数を常設の警告欄に表示します。
  時間帯が完全に同じ場合の優先順位は行・保存配列順です。
  最初から廊下内にいるロボットの退出を優先します。
  停止したままで退出予定がない場合は待機時間を捏造せず、実行不可を明示します。
  相互待ち計画が収束しない場合は、成立しなかった完了時刻で後続だけが進まないよう、
  表示・イベントを含むマップ全体の実行を停止します。
- 人／ロボット・ロボット同士の連続軌跡から最接近を計算し、
  短い時間の交差・停止中の相手・廊下入口で待つ相手も警告します。
  人はグループの代表位置なので、群衆の全員を個別に予測するものではありません。
  人との接触予測は自動で無理な経路変更をせず、待機・時刻・経路の調整を促します。
- 保存済みの不正経路は失敗・停止状態として表示します。新しい不正経路は登録できません。
  既存の不正経路を1つずつ修正できるよう、変更していない既存不正項目の存在だけで
  他の修正を妨げないようにしています。
- **予測はシミュレーション限定です。実機の衝突回避・非常停止・安全保証ではありません。**
  入力されたMAPや寸法、実際の通行幅、人物の動き、測位ノイズ、停止距離の検証が別途必要です。

### 負荷対策

編集時に`compilePlan(map)`で実行計画を作り、再生時は`samplePlan(plan, time)`で
計画済みの軌跡を補間します。UIは変更後の不変なmapオブジェクトごとに計画をキャッシュし、
Undo／Redo・読込・行の除外・MAP編集で必ず別の計画になります。
外部でmapを直接書き換える場合は、再度コンパイルしてください。
静的な床・経路・部屋イベント・表示を毎フレーム作り直さず、再生描画は最大30fpsに制限しています。
2,000項目の計画・状態取得には測定付きの回帰テストがあります。
モデル計算の予算は計画2秒未満・平均状態取得16ms未満で、SVG描画や実機処理の時間保証ではありません。

### シナリオ作成の操作

- ロボットを追加すると、実サイズの車体をマップに表示して「シーケンスを一括設定」を開きます。
  名称・種別・ID・初期位置と、動作ごとの開始・秒数・目的地・向きをまとめて編集し、
  「適用」で1件の編集履歴として保存します。キャンセルは追加済みの行を残し、未適用の設定だけ破棄します。
- ロボットの行・バー・MAP上の車体のダブルクリックは、すべて同じ一括設定を開きます。
  左の動作一覧で選び、従来の「移動」と共通のMAP・移動前後の車体・経路・自由座標／Shift制約で編集します。
  MAPクリックは候補の選択だけです。何度でも選び直せ、最後に一括設定の「適用」で確定します。
  初期位置の小画面も「適用」まで閉じず、そこで適用しても一括設定内の作業コピーだけを変更します。
  ロボットの移動追加も一括設定へ統一し、未適用の前動作の移動先を次の移動の出発点へ反映します。
  人・部屋・画面表示の個別編集は維持します。
  一括設定の↑↓で動作順を入れ替えます。表示番号は時刻順で、実行順を固定するIDではありません。
- Ctrlクリックで複数バーを選択し、Shiftクリックで同じ行の範囲を追加選択します。
  選択したバーのドラッグで行をまたいでまとめて移動し、相対間隔を維持します。
  開始・長さは下端の秒数入力でもまとめて調整できます。長さは各バーに同じ秒数を加減します。
  グループ操作で負時刻・行内重複・編集ロックがある場合は全体を適用しません。
  単一バーの従来操作は維持し、行内重複があれば再生エラーとして表示します。
- 行名をドラッグすると表示順を変更できます。実行時刻・ロボットIDは変えません。
  「除外」はプレビュー対象外、「固定」は編集ロックです（旧M／L表記）。
- 初期位置のMAP指定は実際の車体と向きを表示し、壁・家具・領域外など配置できない理由を表示します。
  車体サイズは盤面上100mm角のままです。実機80cm角との縮尺対応は別途合意が必要です。

### ロボットの旋回とプレビュー表示

新規プロジェクトと新版オフィスは、ロボットのみ移動先の方向に向きを変える旋回を独立バーとして配置します。
人間は回転表示も旋回バーも使わず移動します。読込時に既存の人間の旋回バーを削除し、
他のバーの時刻は詰めずに保持します。旧版で旋回を追加した保存済みシナリオは、
その分の時間の空きが残ります。自動保存の元データは
`robot-scene-studio.backup.before-human-turn-removal`へ退避します。
旋回中は位置を固定し、直進中は向きを固定します。既存プロジェクトはシーケンス上部の
「旋回を配置」（全マップに旋回バーを追加）で全マップ共通に有効化できます。
旋回時間は原則90°/秒（0.1秒単位）です。時間軸を正本とし、
旋回挿入位置以降のバーは全行で同じ秒数だけ後ろへ動かします。
挿入位置をまたぐバーは実行時間を延ばすため、解錠期間やイベント表示も追従します。
手動旋回が既に正しい方向を向いている場合は重複追加しません。
有効化後は移動の追加・目的地や初期位置の編集にも適用します。
不要になった自動旋回を削除しても、既に挿入された時間は自動で詰めません。
独自に開始時刻を合わせたデータは先にJSON保存→適用→バー・連携・警告を確認してください。
元に戻すで適用前へ戻せます。JSONはv4のまま、`facingTurns`と旋回の`facingFor`を追加します。
旧版でも明示的な旋回バーとして再生できますが、移動編集に伴う旋回の追従は新版のみです。

実行プレビュー右下の「全画面」で、展示用にマップだけを画面の四辺まで表示します。
見出し・座標・余白・編集用パス・選択枠を隠し、マップ上のクリックで編集を開かないようにします。
マウスを動かすと透過の再生バーが現れ、操作せず約2.4秒経つとカーソルとともに消えます。
バーで再生／一時停止・先頭／編集点移動・シーク・ループ・速度変更・全画面終了ができます。
Tabでもバーを表示して操作でき、キーボードフォーカスがある間とシーク操作中は隠しません。
16:9モニターを推奨します。異なる縦横比では全マップを欠けずに四辺へ合わせるため縦横に伸縮します。
再生時刻・保存座標・データの縮尺は変わりません。通常画面へ戻ると従来の縦横比へ復帰します。
「全体表示」ボタンも同じ全画面表示を開きます。倍率だけを戻す場合は「拡大」の「全体」を選びます。
Escまたは「全画面を終了」で元のレイアウト・ズームに戻れます。
全画面APIが利用できない場合は理由を通知し、ブラウザー画面内で最大化します。
EVは平面図に合わせた俯瞰のかご床・金属枠・手すり・階数パネルに変更しています。

部屋内のロボットは実際の位置と種別に応じて「掃除中」「監視中」「配送中」を表示します。
移動・旋回中は作業表示へ切り替えず、本体を表示します。エントランスの通過も同様です。
作業表示中は対象ロボット本体と追従表示・選択枠を非表示にし、退室後に再表示します。
行を選択していても本体は表示しません。位置計算・接触判定・ドア制御は継続します。
退室・除外すると表示を解除します。廊下と充電領域内には作業表示を出しません。
これは在室とロボット種別によるシミュレーション表示で、実機からの作業完了通知ではありません。
会議などの明示的なイベント表示は別に残します。

自動ドアは「解錠中」だけでは開きません。その開口を横断する現在の移動バーに
対応する人物・ロボットが近づいた場合だけセンサーで開きます。
全開でも枠・レールを残し、部屋の作業ハッチやイベントより手前に描きます。
扉パネルは引き続き開口内でクリップし、隣室へはみ出しません。
扉を横切る移動バーの開始前0.6秒から接近判定につなぎ、終了後0.6秒で閉じるため、
直前の旋回や入室後の待機との境目で瞬間的に全開／全閉になりません。
車体が開口を占有している間は開放を優先します。解錠バー・移動時刻・通行判定は変えません。
近くにいるだけ・廊下を平行に通るだけの物体では開きません。
開口の直近に車体・人物が残る場合と、通過中に解錠期間が終わった場合は安全のため開放保持します。
循環条件付き旧データの退避・変換・JSON読込、接続なしでの削除・Undo/Redo・再読込、
他行の除外に影響されない開始、待機、人物の入室・会議表示と初期画面での人物行を検証します。
816×639の小さい画面でもMAPと人物の先頭行が画面内に収まり、末尾行までスクロールできます。

## 起動

通常起動とモデルテストには外部依存は不要です。ブラウザーテストだけ開発依存を使用します。

```powershell
Set-Location robot-scene-studio
npm test
npm start
```

`http://localhost:3100` を開きます。終了はターミナルでCtrl+C。
別ポートは `$env:PORT="3101"` を設定して起動します。
更新時はブラウザーをCtrl+F5で読み直してください。

UIの回帰テストは`npm ci`後に`npm run test:browser`。WindowsのEdgeをヘッドレスで使用します。
専用ポート3117と独立コンテキストを使い、利用者の3100番の作業データは変更しません。
詳細は[引継ぎの検証手順](INTEGRATION.md#検証と再実行)を参照してください。

## 保存形式と互換性

新規・読込プロジェクトは **`robot-scene/v4`**（壁・独立設備・ストーリー確認の拡張を保存する場合は **`robot-scene/v5`**）、各マップは
`executionMode: "timed", timelineOnly: true`です。v4のバー位置・実行秒数は保持し、
接続条件と合流だけを除去します。v2／v3は従来の時間軸変換処理で座標をセル中央へ、
目安の幅を実行秒数へ変換します。読み込み後は全マップが時間軸専用になり、
Undoで旧条件を復活させることはありません。旧モデルAPIを直接使う場合の互換動作は別途維持します。
この版で保存した条件なしのJSONは旧版で開けないため、元JSONも必ず残してください。
元JSON保存→更新→通行・施錠・行内重複の確認→再生確認の順で適用してください。
旧版へ戻す際はコードと更新前JSONを両方戻します。段階導入は旧JSONを別に保管して行ってください。

自動保存は `robot-scene-studio.v4`。v4がなければv3→v2の順で復元し、
元の旧キーを削除・上書きしません。複数バージョンを併用して編集しないでください。
同じv4の複数タブはWeb Locksと保存内容の世代比較で競合を検出します。
競合したタブは自動保存を停止し、画面の作業を残してJSONへの退避を案内します。
JSON保存→他のタブを閉じる→再読込→必要なJSONを開く、の順で復旧してください。
Web Locks非対応のブラウザーでは安全な排他保存ができないため自動保存せず、JSON保存を案内します。
自動保存の復元に失敗した場合も、元データを残してそのタブの自動保存を停止します。
まず元のlocalStorage値を開発者ツール等で退避し、JSON保存で現在の作業も確保してください。
退避後に破損したキーだけを除去して再読込し、有効なJSONを開くと自動保存を再開できます。
容量不足時はデータを削除せずエラーを表示します。容量を確保して次の編集を行うかJSON保存してください。

以下は旧v3の契約の参考です（現在の新規作成の仕様ではありません）。

`robot-scene/v3`、マップの `executionMode: "ordered"` で
左→右の順序実行を指定します。v2は従来のトリガー実行のまま読み込み、
勝手に実行順を変更しません。既存マップは「順序実行へ切替」の確認後に変更できます。
先に元のJSONを保存してください。切替はUndoで戻せます。
他マップの方式は変更せず、元の条件・位置・IDを維持します。
既存条件と配置順が循環する場合は切替を拒否するため、先に条件か配置を変更してください。
v3は旧版アプリでは読み込めません。段階移行はマップ単位で可能ですが、
1マップでも順序実行にするとプロジェクトの保存形式はv3になります。

自動保存は `robot-scene-studio.v3` に保存します。初回はv3がなければv2を読み込み、
元のv2キーは上書き・削除しません。旧版へ戻す際は、切替前のv2 JSONと旧ソースを使ってください。
以後のv3での編集は旧v2自動保存へ反映されないため、併用して編集しないでください。

継続時間付きクリップだったv1とは意味が違うため、
v1 JSONを黙って変換しません。読込時は明示的に拒否し、現在の編集を保持します。
v1のlocalStorageも削除・上書きしません。
更新前のJSONと旧ソースを必要に応じて別途保管してください。
v1データは旧版で開くか、この版で時間軸のバーを作り直してください。
既存のロボット測位版やその出力形式には変更しません。

## 複数マップ・グリッド式マップ作成

- 上部のタブでマップと対応するシーケンスを同時に切り替えます。再生は一時停止して先頭に戻ります。
- 「＋ シーケンス」でマップの縮小画像を選びます。既存のマップを選ぶと
  別シーケンス用にレイアウトだけコピーします。「新しくマップを描く」を選んだ場合は
  作成ポップアップが開き、「適用」するまで追加しません。
- 上部の**ゾーニングモード／部屋編集モード**で切り替えます。
  ゾーニングでは上部の領域選択・追加・削除と描画ツールで形を作ります。
  常時表示の左スクロールメニューは廃止しました。
  部屋編集では、図面上の部屋・廊下をクリックしたときだけ左側に編集メニューが開き、
  名称・種別・床材・色・家具・ドアを編集できます。別の部屋をクリックして切り替えます。
  選択ツールで空白をクリックするとメニューを閉じます。
- マップ編集中は**Ctrl+Zで1操作戻す、Ctrl+Yで1操作やり直す**。
  上部の「戻す／やり直す」ボタン、Ctrl+Shift+Zにも対応します。
  描画は1ドラッグを1操作として扱い、部屋追加・削除、ドア・家具、属性変更も対象です。
  履歴はポップアップ内で最大100操作。新しい編集後はやり直し履歴を破棄します。
  「適用」まではシーケンス側の履歴と独立し、キャンセルでマップ編集全体を破棄します。
- **16:9／32列×18行**のグリッドで部屋・廊下を作ります。1セルは50座標単位です。
  **50インチ・16:9の表示面（ベゼルを除く）約1106.9×622.6mm**を基準にすると、
  **1セルは約34.6×34.6mm**です。編集画面下部にも表示します。
  対角50×25.4mmから計算した概算であり、機種の実測値や測位の校正値ではありません。
  保存する座標系は従来どおり比率座標で、50座標単位＝50mmではありません。
  矩形の範囲指定やセルの塗り足し／消去でL字型の領域も作成できます。
- エリアごとに名称・部屋／廊下の種別・床材を設定。木目・タイル・カーペット・
  コンクリートをプレビューへ反映します。机・椅子・植栽を配置でき、向きも変更できます。
- 部屋編集で部屋をクリックし、家具の種類を選んで「家具」ツールでドラッグします。
  **ドラッグした長方形の範囲を1個の家具として作成**します（1セル単位）。
  デスク・チェアは1セルでは従来の見た目、複数セルでは**長机・長椅子**に切り替わります。
  観葉植物は縦横のセル数を自由に選べ、範囲に合わせて植栽表示を拡縮します。
  ドラッグ中・選択中はセル数と50インチ換算の概算mm寸法を表示します。
  家具全体が同じ部屋内に収まる必要があり、他の家具や空白、別の部屋とは重ねられません。
  90°回転では左上の基準セルを保持して占有範囲の縦横を交換します。
  回転後にはみ出し・重なりが生じる場合は理由を表示して変更を拒否します。
  配置・回転・削除はそれぞれ1操作としてundo／redoできます。
- ドアツールで壁に近づけるとオレンジ色の配置候補が出ます。
  壁の内外どちらからでもクリックで最寄りの壁へスナップします。通常は辺の指定不要です。
  新規自動ドアはクリック位置から右／下へ6セルを1操作で配置します。
  同じ隣接領域に面した有効な境界が足りなければ配置しません。
  既存ドアを再クリックすると選択し、「選択物を削除」で消せます。
  壁の開口と開閉方向を模式表示します。
- 既存データの同じ部屋・同じ向きの隣接ドアは、従来どおりまとめて表示します。
  新規の6セル開口は個別の設備として保持し、削除も開口全体で行います。
  元の配置IDは保持し、通行データの `doors[].memberIds` に統合元IDを保存します。
- 「マップを編集」または左の「マップを編集する」で再編集できます。
  キャンセルは変更を破棄。適用はundo／redoに対応します。
- 追加しすぎた領域は「領域を削除」で取り消せます。
  行・初期位置・アクションから参照される領域は削除を拒否します。
  削除が必要な場合は先に関連付けを解除してください。
- 新しく作成した部屋・廊下には対応する部屋行を追加します。
  再編集でも既存の部屋ID・行・アクションは保持します。
  部屋の形を変えても既存ウェイポイントや初期位置は自動移動しません。
  適用後に位置と在室判定を確認し、必要な点を手動で調整してください。
- マップごとに部屋・床・ドア・家具・行・アクションをJSON保存します。
  各シーケンスの時間軸は独立しています。
- **画像の新規読み込みは廃止**しました。既存v2の画像入りJSONは引き続き読み込めます。
  既存マップをグリッド式に編集して適用すると画像背景は除かれます。
  元画像が必要なら先にJSONを保存してください。キャンセルでは除かれません。
- ステージ右上の拡大で150～400%にし、スクロールで細部を確認。「全体表示」で戻します。
- 左下(0,0)、右上(1600,900)、X右・Y上の既存座標を維持します。
  既存の矩形部屋はマップ編集時にグリッドへ対応づけます。
  実測図面の寸法校正や測位との自動位置合わせはありません。
- 移動は直線のみで、自動経路探索は行いません。
  v4では壁・家具に接触する指定を拒否し、廊下待機・接近予測を行います。
  旧方式では表示用です。どちらも実機への指令は送信しません。

## 行とパレット

右のパレットで行を追加します。

| 行 | 内容 |
|---|---|
| ロボット | IDと初期位置・向きを持つ。1台1行。マップ内でID重複不可 |
| 人間グループ | 人数1～1000人を設定。全員が同じ経路・時間軸で移動 |
| 部屋 | マップ上の部屋へ関連付け、状態の発生／終了を配置 |
| 表示・イベント | 単独項目用でもクラスでまとめた行でも利用可能 |

人物は上から見た模式アイコンで表し、最大5体を代表表示＋「×人数」で示します。
初版では途中のグループ分割なし。別行動する人物は最初から別行に分けます。
部屋は左の「＋」からマップ編集を開いて追加できます。
グリッド式の部屋の形・床材・家具はマップ編集で変更します。
旧版の矩形部屋は従来の座標編集も保持します。

マップ上のロボット・人間をクリックすると、対応する行をハイライトしてその行まで
シーケンスをスクロールします。部屋をクリックすると関連する部屋行へ移動します
（複数ある場合は選択中の関連行、なければ先頭の関連行）。行がない部屋は追加方法を案内します。
マップ上の表示テキスト・イベントのハッチングやラベルをクリックすると、
現在の表示を生成したアクションと行を選択し、カードが見える位置まで縦横にスクロールします。
同じ対象IDの表示が更新された場合は、更新後のアクションへ移動します。
この選択操作は再生時刻や保存データを変更しません。

- パレットをクリック、行の空き領域をダブルクリックでも追加できます。
- 既存カードのダブルクリック、選択後の「編集」で同じポップアップを開きます。
- 編集画面は **左：最小限の設定／右：常時MAP** の2ペインです。
  床・壁・家具・ロボットの見た目と表示／イベントの描画は、実行プレビューと共通です。
  通常のデスクトップではスクロールせず設定と適用ボタンを確認できます。
  狭い画面ではMAPを上に置く縦並び・スクロールへ切り替えます。
- 移動は左で **アクション名と実行秒数** を設定し、右MAPをクリックして移動先を指定します。
  **白い輪郭：移動前／ミント：移動後／破線：直線経路** を同時に表示します。
  移動前の位置は、時間軸で先行する項目から算出します。
  先行項目が通行エラーの場合は参考表示である旨を表示します。
  移動先の部屋もクリック位置から自動設定します。L字型の空白は室外になります。
- 左の **移動／回転** ボタンで動作を切り替えます。回転は **回転後の角度と秒数** のみを追加設定し、
  右MAPに回転前後の向きを表示します。
- 表示は **テンプレート（テキスト／案内カード／サイン）と内容** を設定し、
  右MAPで配置します。ロボット・人の行の表示は対象に追従するため、MAP位置指定は不要です。
  改行対応。長文の見た目は22文字程度で折り返し、5行を超える部分は省略記号を付けます。
  元の内容は省略せず保存します。
- イベント発生は **イベント種別・色・模様（斜線／クロス／ドット）・言葉** を設定し、
  MAP上の部屋・廊下をクリックして対象を指定します。模様はゆっくり動きます。
  イベント終了／表示消去は **終了する項目** を名前で選び、MAPに薄く表示される対象を確認します。
  バーの右端または終了／消去項目まで表示を保持します。
- 内部ID、予定横位置、見積もり時間、速度や到着許容値はポップアップに出しません。
  保存する内部ID・開始位置・速度は維持します。開始位置・実行幅はタイムラインで調整します。
  変更は「適用」まで作業コピーだけに保持し、キャンセルで破棄します。
- 項目編集内の変更は「適用」までデータを変更しません。キャンセルで新規追加や設定変更を取り消せます。
- カードの横移動は**開始時刻**を変更します。
- v4ではカード右上のハンドルを左右へドラッグすると**実行秒数**を伸縮できます。
  時間軸の縮尺に連動し、0.5〜3600秒で保存します。
  ハンドルにフォーカスして左右キーでも0.5秒ずつ調整できます。
  移動・回転速度と表示・イベント継続時間もバーの幅に合わせて変わります。
- 人物・ロボットの初期姿勢と人数、行名／クラス名、色、部屋の関連付けは右側で編集します。
- ロボット・人の行、またはそのアクションを選び、右側の **「初期位置を設定」** を開くと、
  **「MAPで初期位置を指定」** で位置、`初期の向き yaw` で向きを指定できます。
  「適用」で保存し、キャンセルでは変更しません。undo／redoにも対応します。
  初期位置はシーケンス開始前の行設定で、時間軸に置くアクションではありません。
  実行途中のプレビューは既存アクションも反映するため、初期状態の確認は先頭へ戻してください。
- M＝プレビュー除外、L＝行のアクション編集ロック。他行の除外はその行の開始条件になりません。

## 時間軸だけで実行

接続操作・待ち条件の編集・合流はありません。カード色で待機／実行中／完了／実行不可を示します。
時刻を前後にシークしても同じバー配置から状態を再計算します。
人物の退室や清掃開始も、それぞれのバーを実行したい時刻へ置いて設定します。
通行不可・施錠・同じ行の時間重複は停止エラーのままです。時計を止めたり、バーを自動でずらしたりしません。

## 移動・表示・部屋状態

### 直線移動と、その場で向き変更

- 「移動」の編集画面の **移動／回転** ボタンで直線移動と、その場での回転を選択します。
- 直線移動は開始位置から指定座標までの1本の線です。曲がる場合は移動を2個以上置き、
  同じ行に時間が重ならないよう左→右に並べます。自動で曲線・迂回経路を作りません。
- 向き変更は、そのアクションの開始時点の位置と所属部屋を保持したまま、
  **回転後の角度（yaw）と回転にかける秒数** で回転します。ロボット・人の両方で使用できます。
  目標へは最短角度で回転し、ちょうど180°の差は時計回りを選びます。
  例えば90°差を2秒と指定すると、1秒後は45°差になり、2秒で完了します。待機は加算しません。
- この編集画面で適用する直線移動は、開始時の向きを保ちます。向きは回転アクションで変更します。
  旧データの移動中のyaw補間は、編集して適用するまでは維持します。
- 既存の `type: "move"` はそのまま使えます。新しい `motion: "rotate"` は
  `rotationSeconds` を保存し、`motion` のない既存データは直線移動として扱います。
  `rotationSeconds` のない旧回転は従来の `angularSpeed` で再生し、
  編集時に同じ回転時間へ換算します。表示テンプレートは `displayTemplate`、
  イベントの色・模様は `hatchColor`／`hatchStyle` として保存します。
  新機能のデータを旧版で開くと回転を直線移動と解釈するため、最新版同士で共有してください。
  新フィールドを旧版で開くと回転秒数や表示の見た目が正しく再現されません。
  実機への指令は送信せず、速度・回転秒数はプレビュー用です。

### 移動

行の直前の位置からMAPで指定した座標まで直線移動します。
L字型などの部屋も実際に塗られたセルで在室判定し、外接矩形の空白部分は室外です。
現在のエディターは指定した実行秒数だけで到着時刻を計算します。待機や条件で時刻を変更しません。
旧モデルAPIの到着判定設定 **距離15座標単位（50インチ換算で約10.4mm）以内を0.3秒維持** は
互換データとして保存しますが、固定時間軸の再生には加算しません。
ロボットの見た目は1辺約144.54座標単位（100mm、2.89セル）です。
距離許容は車体寸法とは別の暫定値です。回転完了の角度許容は **±10°** です。
新規移動・編集して適用した移動に反映し、未編集の旧データを一括書き換えません。
実機で車体・測位ノイズ・停止誤差を検証し、必要なら実装の固定値を調整してください。
許容距離・向き許容差も保存しますが、**実測入力へつながっていないため、
本物の測位による到着判定を行ったことにはなりません。**
同じ対象へ競合する移動を同時に実行しないよう、バーの時刻を調整してください。

### 表示と消去

表示はバー左端で反映し、バー右端または消去アクションで消えます。
対象IDで消去対象を特定します。同じ行に複数の表示を置いても別IDなら別項目です。
ロボット／人物行の表示は対象に追従し、表示行は座標指定です。どちらもテンプレートを選べます。
動画・画像サイネージ、HTML、音声、実機表示機器への配信は未対応です。

### イベント発生と終了

会議中・停電・火災は部屋に動くハッチングとラベルを表示します。
バーの幅が継続秒数です。バー右端またはイベント終了アクションで表示を消します。
複数の状態は別対象IDで共存し、終了は対象IDと部屋を指定します。
発生／終了は演出用であり、現実の異常検知や避難制御ではありません。

### 在室表現

- 人物／ロボットが部屋へ到着済みで、その部屋に状態イベントが表示されると、
  個別アイコンを隠して部屋の「人 ○名／ロボット ○台」へ集約します。
- イベント発生が後からでも同様です。未到着・室外の対象を勝手に在室させません。
- 状態表示がすべて終了しても、在室表示は維持します。
- 別の部屋／室外へ退出する移動が始まると、その対象だけアイコンへ戻ります。
- 人数は行の人数で合算。複数状態でも二重計上しません。
- 在室中でも位置・向き・トリガー状態は保持します。
  行を選択中は編集用に薄くアイコンを表示し、隠れた位置を確認できます。

## 保存・復旧・注意

「プロジェクト保存」で**全マップの図面・家具・シーケンスを含むJSON**をダウンロードします。
旧版の背景原画像も残っている場合は含みます。
「開く」で検証して復元。不正なJSONは作業を置き換えません。
読込は80MiB以下。背景を多数入れると大きくなるため、画像容量を調整してください。
最大8マップ、全体2000アクション。背景のエンコード済みデータは全マップ合計70MiBまでです。
機微情報を含む図面はJSONにも含まれます。共有範囲に注意してください。

localStorageへの自動保存は容量制限があります。高画質画像で失敗した場合は画面下に通知します。
**JSON保存を正本として使用してください。** ダウンロード完了を利用者側で確認します。
ブラウザー側の自動保存は同じブラウザー・オリジンだけで復元されます。
メモリー内のundo／redoは40操作を目安に保持し、ページを閉じると失われます。
確定操作の永続履歴は別途PC上へ全件保存し、「編集履歴」から再適用できます。
新規作成・マップ削除・プロジェクト切替は先に保存してください。

### 外部連携用の通行情報

JSON保存・自動保存では、各マップに派生データ `navigation` を付加します。
`schema: "floor-navigation/v1"`。元の部屋セル・ドア・家具もそのまま保持します。
壁・ドア等を編集した場合は保存時に元データから再生成するため、`navigation` 自体を
手編集しても次の保存では反映されません。

- 座標：X右・Y上、左下(0,0)〜右上(1600,900)、mmではない比率座標。
- `grid`：32列×18行、セルサイズ50。セル番号だけは左上起点・行優先の0〜575。
- `cells`：全576セルの部屋ID、`traversable` と理由
  `floor`／`furniture`／`unassigned`。領域外・未定義セルは通行不可として出力します。
- `walls`：通行境界の線分 `x1,y1,x2,y2`。共有壁は重複排除し、
  ドアのある壁は実際の描画と同じ両端6座標単位を残して開口として除きます。
  隣接ドアの間には壁を残さず、統合した連続開口を出力します。
- `doors`：ID・所属部屋・隣接部屋・開口線分。
  `state: "unspecified"` で、**実際に開いている・通行可能とは保証しません**。
- `obstacles`：家具のID・種類・向き・占有矩形。安全側の初期表現として
  家具は選択した全セルを占有扱いにします。見た目の輪郭とは異なります。
  複数セル家具では矩形の `width`／`height` もその範囲になります（比率座標単位）。
  元データの `floorPlan.furniture[].cells` に占有セルを保存し、`cell` は左上の基準セルを維持します。
  `cells` のない旧単セル家具は引き続き読み込めます。複数セル家具を旧版アプリで再編集すると
  大きさや通行判定が正しく扱われないため、この機能を含む版を使用してください。
- グリッド化していない旧マップは `status: "unavailable"`。
  画像から壁を推測して安全そうな通行情報を生成することはしません。

これは地図の連携用データであり、自動経路探索・衝突防止ではありません。
セルが通行可でも壁を横断できるとは限らないため、連携先は必ず壁線・開口・
ドア状態・ロボットの車体サイズと安全余裕を合わせて判定してください。

ショートカット：Space再生／一時停止、Ctrl+S保存、Ctrl+Z／Ctrl+Shift+Z undo／redo、
Ctrl+D複製、Delete削除。ポップアップ中や入力中は誤操作を避けます。
